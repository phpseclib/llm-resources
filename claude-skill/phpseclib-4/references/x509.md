## What an X509 object is

An `X509` object is a thin wrapper around an instance of `phpseclib4\File\ASN1\Constructed`. The `Constructed` object holds the parsed ASN.1 structure of the certificate; the `X509` wrapper adds helpful methods (`getPublicKey()`, `getSubjectDN()`, `setExtension()`, etc.) on top.

Three consequences worth internalizing:

1. **Every certificate field is accessible two ways** — through a helper method or through `ArrayAccess` on the parsed ASN.1 structure. `$x509->getPublicKey()` and `$x509['tbsCertificate']['subjectPublicKeyInfo']` get you to the *same object* — both return the `PublicKey` instance (RSA/EC/DSA, depending on the cert). The helper exists mostly to make the access path shorter and to throw a typed exception if the slot couldn't be decoded as a `PublicKey`.

2. **The fields are pre-decoded on parse via `$rules`.** When `X509::load()` runs, it registers rules with `ASN1::map()` that say "when this field is accessed, decode it as a `PublicKey`," "when this DN is accessed, normalize it," etc. By the time you reach the field via ArrayAccess, the typed object is already there. The implementation is essentially:

   ```php
   $rules['tbsCertificate']['subjectPublicKeyInfo'] = function (Constructed &$key) {
       try {
           $key = PublicKeyLoader::load($key->getEncoded());
       } catch (NoKeyLoadedException) {
           // leave $key as a Constructed; getPublicKey() will throw on access
       }
   };
   ```

   The helper methods (`getPublicKey()`, `getSubjectDN()`, etc.) are mostly thin checkers — they confirm the slot contains the expected typed object and throw if not. They don't do the decoding work; the rules attached at parse time do.

   The practical takeaway: ArrayAccess is *not* a slower or lower-level path. It returns the same friendly objects the helpers do. Use whichever reads better in context.

3. **`print_r($x509)` produces a debugging tree** of the parsed ASN.1 structure via `__debugInfo()`. Use it freely — it's the single best way to figure out what's actually inside a certificate when something's wrong.

## Loading certificates

```php
public static function load(string|array|Constructed $cert, int $mode = ASN1::FORMAT_AUTO_DETECT): X509
```

```php
use phpseclib4\File\X509;

$x509 = X509::load(file_get_contents('cert.pem'));
```

`X509::load()` accepts PEM or DER bytes and auto-detects which. There is no separate `loadDER()` / `loadPEM()` choice. Returns a hydrated `X509` object.

The `$mode` parameter is one of `ASN1::FORMAT_AUTO_DETECT` (default), `ASN1::FORMAT_PEM`, or `ASN1::FORMAT_DER`. Forcing a specific mode is rarely needed; auto-detect handles both correctly. The mode is ignored when the first argument is already an `array` or `Constructed` (those cases skip the string-decoding step entirely, and accept whatever shape they receive — there's no validation, so bad input will produce random exceptions later).

Bad input throws — usually `phpseclib4\Exception\UnexpectedValueException`. Wrap in try/catch if the source is untrusted.

There is no `loadX509()` method in 4.0. If you see `$x509->loadX509($pem)` in code, that's a 3.0 pattern and needs migrating to `X509::load($pem)`.

## Reading certificates

### Inspecting the whole structure

```php
print_r($x509);
```

Triggers `__debugInfo()` and prints the parsed ASN.1 tree. Useful for figuring out what fields are present and what they contain.

### `getPublicKey()`

```php
public function getPublicKey(): PublicKey
```

Returns an instance of `phpseclib4\Crypt\Common\PublicKey` (specifically `RSA\PublicKey`, `EC\PublicKey`, or `DSA\PublicKey`).

```php
echo $x509->getPublicKey();
// -----BEGIN PUBLIC KEY-----
// MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQKBgQDe...
// -----END PUBLIC KEY-----
```

Throws `phpseclib4\Exception\UnexpectedValueException` if the key is in a format phpseclib doesn't parse. For untrusted input, guard with `hasPublicKey()` or wrap in try/catch.

If the key format isn't one phpseclib parses, the `subjectPublicKeyInfo` slot will hold a `phpseclib4\File\ASN1\Constructed` instead of a `PublicKey` — `getPublicKey()` throws in that case. You can still get at the raw bytes via the slot directly:

```php
$slot = $x509['tbsCertificate']['subjectPublicKeyInfo'];
// $slot is a Constructed if parsing failed, otherwise a PublicKey.
if ($slot instanceof PublicKey) {
    // normal case
} else {
    $rawBytes = $slot->getEncoded();
    // inspect / handle the unparseable key yourself
}
```

### `hasPublicKey()`

```php
public function hasPublicKey(): bool
```

Returns `true` if the certificate's `subjectPublicKeyInfo` slot decoded into a real `PublicKey` object, `false` otherwise. Useful for guarding `getPublicKey()`.

```php
if ($x509->hasPublicKey()) {
    $key = $x509->getPublicKey();
}
```

What "false" actually means here: the SPKI field is always present in an X.509 cert per RFC 5280 — it's never optional. What `hasPublicKey()` is really telling you is whether phpseclib was able to recognize the field's contents as a public key. Two cases produce `false`:

1. **The key is in a format phpseclib doesn't support.** The bytes are there, they encode some key, but phpseclib's `PublicKeyLoader` doesn't know that format. The SPKI slot ends up as a `Constructed` (per the `$rules` callback that catches `NoKeyLoadedException`).
2. **The SPKI is a placeholder.** A freshly-constructed `new X509()` with no public key set has an SPKI with algorithm OID `0.0` and a zero-length BitString — structurally valid but semantically empty. The loader can't make a `PublicKey` out of nothing, so the slot stays as a `Constructed`.

In either case you can reach into `$x509['tbsCertificate']['subjectPublicKeyInfo']` to inspect what's actually there.

### `listExtensions()`

```php
public function listExtensions(): array
```

Returns an array of the extension names (or OIDs) present in the certificate:

```php
print_r($x509->listExtensions());
// Array
// (
//     [0] => id-ce-keyUsage
//     [1] => id-ce-extKeyUsage
//     [2] => id-ce-subjectAltName
//     [3] => id-ce-basicConstraints
//     [4] => id-ce-cRLDistributionPoints
//     [5] => id-ce-authorityKeyIdentifier
//     [6] => id-ce-subjectKeyIdentifier
//     [7] => id-pe-authorityInfoAccess
// )
```

### `getExtension($name)`

```php
public function getExtension(string $name): ?array
```

Returns an array representing the first instance of the named extension, or `null` if it's not present.

```php
$ext = $x509->getExtension('id-ce-cRLDistributionPoints');
// [
//     'extnId' => 'id-ce-cRLDistributionPoints',
//     'critical' => false,
//     'extnValue' => phpseclib4\File\ASN1\Types\BaseType Object { ... },
// ]
```

You can pass either the symbolic name (`id-ce-keyUsage`) or the dotted OID (`2.5.29.15`). Both work.

The `extnValue` is a typed `BaseType` instance — call appropriate methods on it depending on the extension, or cast it to a string for textual representations.

### `hasExtension($name)`

```php
public function hasExtension(string $name): bool
```

```php
if ($x509->hasExtension('id-ce-cRLDistributionPoints')) {
    // ...
}
```

Cleaner than `getExtension(...) !== null` when you only need a boolean.

### Multiple instances of the same extension

If a certificate has the same extension multiple times — which RFC 5280 §4.2 forbids ("A certificate MUST NOT include more than one instance of a particular extension"), but occurs occasionally in non-compliant real-world certs — `getExtension()` returns only the first. To enumerate all of them, you have to walk the ASN.1 structure via ArrayAccess.

## Creating certificates

### Minimal certificate

```php
use phpseclib4\File\X509;

$x509 = new X509();
echo $x509;
```

This produces a structurally valid but semantically empty certificate:

```
-----BEGIN CERTIFICATE-----
MEUwO6ADAgECAgEBMAMGAQAwADAeFw03MDAxMDEwMDAwMDBaFw03MTAxMDEwMDAw
MDBaMAAwCDADBgEAAwEAMAMGAQADAQA=
-----END CERTIFICATE-----
```

It has placeholder values where a real certificate would have content: an empty subject DN, an empty issuer DN, no extensions, no real signature, and a placeholder `subjectPublicKeyInfo` (algorithm OID `0.0` and a zero-length BitString — see [`hasPublicKey()`](#haspublickey) for why this isn't the same as "no public key field"). OpenSSL will choke on it. It's mostly useful for testing or for understanding what defaults exist.

Three fields are auto-populated:

- **Serial number** — a random 160-bit positive integer.
- **Start date** — the current time.
- **End date** — one year from the current time.

Override each as needed:

```php
public function setSerialNumber(string|BigInteger $serial, int $base = 256): void
public function setStartDate(\DateTimeInterface|string $date): void
public function setEndDate(\DateTimeInterface|string $date): void
```

```php
$x509->setSerialNumber('12345');                   // string, base-256 by default
$x509->setSerialNumber('FF', 16);                   // hex
$x509->setSerialNumber(new BigInteger(12345));      // BigInteger (base is ignored)

$x509->setStartDate('-1 day');                     // accepts DateTimeInterface or DateTime-parseable string
$x509->setEndDate('+5 years');
$x509->setEndDate('lifetime');                     // RFC 5280's "no well-defined expiration"
                                                    // (December 31, 9999 23:59:59 UTC)
```

CA/Browser Forum currently recommends server certificate validity windows between 8 and 25 years for root CAs, much shorter for end-entity certs — but phpseclib won't enforce that, you have to choose appropriate dates yourself.

### Setting the public key

```php
public function __construct(PublicKey|CSR|null $cert = null)
public function setPublicKey(PublicKey $publicKey): void
```

Three equivalent ways to attach a public key:

```php
use phpseclib4\Crypt\EC;

$privKey = EC::createKey('nistp256');
$pubKey = $privKey->getPublicKey();

// 1. Constructor argument
$x509 = new X509($pubKey);

// 2. setPublicKey
$x509 = new X509();
$x509->setPublicKey($pubKey);

// 3. From a CSR (also copies the subject DN and requested extensions)
$csr = CSR::load($csrPem);
$x509 = new X509($csr);
```

Use `$x509->removePublicKey()` to clear it.

## Distinguished names (DNs)

An X.509 certificate has both a **subject DN** (the entity the cert identifies) and an **issuer DN** (the CA that signed it). For self-signed certificates these are identical; for CA-signed certs they differ.

### The bare-vs-explicit rule

phpseclib 4.0 has both bare and explicit DN methods:

| Bare (works only if subject == issuer) | Explicit (always safe) |
| --- | --- |
| `getDN()` | `getSubjectDN()` / `getIssuerDN()` |
| `setDN()` | `setSubjectDN()` / `setIssuerDN()` |
| `resetDN()` | `resetSubjectDN()` / `resetIssuerDN()` |
| `addDNProp()` | `addSubjectDNProp()` / `addIssuerDNProp()` |
| `addDNProps()` | `addSubjectDNProps()` / `addIssuerDNProps()` |
| `removeDNProps()` | `removeSubjectDNProps()` / `removeIssuerDNProps()` |
| `getDNProps()` | `getSubjectDNProps()` / `getIssuerDNProps()` |
| `hasDNProp()` | `hasSubjectDNProp()` / `hasIssuerDNProp()` |

The bare versions throw if subject ≠ issuer. For any code that handles arbitrary (non-self-signed) certificates, **always use the explicit variants.**

The full signatures of the DN method family:

```php
// Getters
public function getDN(int $format = self::DN_STRING): array|string
public function getSubjectDN(int $format = self::DN_STRING): array|string
public function getIssuerDN(int $format = self::DN_STRING): array|string

public function getDNProps(string $propName): array
public function getSubjectDNProps(string $propName): array
public function getIssuerDNProps(string $propName): array

public function hasDNProp(string $propName): bool
public function hasSubjectDNProp(string $propName): bool
public function hasIssuerDNProp(string $propName): bool

// Setters
public function setDN(array|string|Element $props): void
public function setSubjectDN(array|string|Element $props): void
public function setIssuerDN(array|string|Element $props): void

public function resetDN(): void
public function resetSubjectDN(): void
public function resetIssuerDN(): void

public function addDNProp(string $propName, string|BaseString|array|Element|Constructed $value): void
public function addSubjectDNProp(string $propName, string|BaseString|array|Element|Constructed $value): void
public function addIssuerDNProp(string $propName, string|BaseString|array|Element|Constructed $value): void

public function addDNProps(string $propName, array $values): void
public function addSubjectDNProps(string $propName, array $values): void
public function addIssuerDNProps(string $propName, array $values): void

public function removeDNProps(string $propName): void
public function removeSubjectDNProps(string $propName): void
public function removeIssuerDNProps(string $propName): void
```

The `$format` parameter on getters is one of the `ASN1::DN_*` constants (see [`getDN`](#getdnformat--asn1dn_string) below). The `$value` parameter on `addDNProp` family accepts strings (interpreted as UTF8String by default), typed `BaseString` instances for explicit string types, raw `Element` instances for ASN.1 byte input, or `Constructed` objects for direct ASN.1 structures (used for composite types like postalAddress).

### `getDN($format = ASN1::DN_STRING)`

Returns the DN in one of six formats:

- **`ASN1::DN_STRING`** (default): an OpenSSL 3.0 CLI-style string like `C = US, O = Internet Security Research Group, CN = ISRG Root X1`. This is what `openssl x509 -noout -text` prints for the issuer/subject lines on OpenSSL 3.0+. See [DN_STRING format change](#dn_string-format-change) below — this differs from what phpseclib 3.0 produced.
- **`ASN1::DN_ARRAY`**: phpseclib's internal nested-array representation, mirroring the ASN.1 RDN sequence structure.
- **`ASN1::DN_OPENSSL`**: a flat associative array mostly compatible with `openssl_x509_parse('...')['issuer']`.
- **`ASN1::DN_ASN1`**: the raw binary ASN.1 encoding. Equivalent to `$x509['tbsCertificate']['subject']->getEncoded()`. Cannot be fed back into `setDN()` as a plain string (wrap in an `Element` to round-trip).
- **`ASN1::DN_CANON`**: a canonicalized binary encoding (UTF8String normalization, lowercased, whitespace collapsed, SET wrappers stripped). Used for matching DNs that differ only in encoding-incidental ways.
- **`ASN1::DN_HASH`**: a hex string of the first 4 bytes of `SHA1(DN_CANON)` as a little-endian 32-bit integer. Matches OpenSSL's `subject_hash` / `issuer_hash` output; used as a directory-lookup hash in CA trust stores.

The constants are on `ASN1`, not `X509` — that was a 3.0 location. In 4.0 they moved to where they conceptually belong.

For the full format details and multi-valued RDN handling, see `references/distinguished-names.md`.

### DN_STRING format change

The output format of `DN_STRING` changed between phpseclib 3.0 and 4.0. For the same DN, here's what different tools produce:

| Tool / version | Output |
| --- | --- |
| phpseclib 4.0 (`DN_STRING`) | `C = \C3\80, O = B, serialNumber = C` |
| OpenSSL 3.0 CLI (`openssl x509 -text`) | `C = \C3\80, O = B, serialNumber = C` |
| PHP `openssl_x509_parse()` on OpenSSL 3.0 | `/C=\xC3\x80/O=B/serialNumber=C` |
| OpenSSL 1.0 CLI | `C=\xC3\x80, O=B/serialNumber=C` |
| phpseclib 1.0 – 3.0 (`DN_STRING`) | `C=À, O=B/serialNumber=C` |

phpseclib 4.0 can *parse* the first two formats via `setDN()` (both round-trip cleanly), but `getDN()` always emits the OpenSSL 3.0 CLI format. The reason: that format eliminates ambiguities the older formats have.

Specifically, the older `/C=US/O=Acme/Inc./CN=…` style uses `/` as both the RDN separator *and* a legal character within values, so a parser can't tell whether `O=Acme/Inc.` is one attribute or two without knowing the schema. The OpenSSL 3.0 format uses `, ` as the separator with escaping for commas inside values, which is unambiguous.

**Practical migration implication:** any phpseclib 3.0 code that string-matches the output of `getDN()` will break in 4.0. For example:

```php
// 3.0: getDN() returned "C=US, O=Acme/CN=example.com"
if (strpos($x509->getDN(), 'CN=example.com') !== false) { /* ... */ }

// 4.0: getDN() returns "C = US, O = Acme, CN = example.com"
// The 3.0 strpos check still matches accidentally (because 'CN=' is a substring
// of 'CN = '), but a check for 'CN=example' or '/CN=' or '=example.com' won't
// behave as the 3.0 code expected.
```

The fix isn't to chase the new string format — it's to stop string-matching `getDN()` output and use the structured methods instead:

```php
// Robust: ask for the specific property
if (in_array('example.com', $x509->getSubjectDNProps('CN'), true)) { /* ... */ }

// Or: get the DN as a structured array
$dn = $x509->getSubjectDN(ASN1::DN_OPENSSL);
if (($dn['CN'] ?? null) === 'example.com') { /* ... */ }
```

If you specifically need the 3.0-style string (e.g., for log compatibility), there is no built-in 4.0 setting for it — you'd build it from the `DN_OPENSSL` array yourself.

### `setDN($props)`

Sets the DN. Accepts strings, arrays, or `phpseclib4\File\ASN1\Element` instances:

```php
// String form (OpenSSL-style)
$x509->setDN('/C=US/O=phpseclib/CN=example.com');
$x509->setDN('C=US, O=phpseclib, CN=example.com');

// DN_OPENSSL array form
$x509->setDN([
    'C' => 'US',
    'O' => 'phpseclib',
    'CN' => 'example.com',
]);

// Multi-valued CN
$x509->setDN([
    'C' => 'US',
    'CN' => ['name1', 'name2'],
]);

// Explicit string type (DEFAULT is UTF8String — use this for PrintableString etc.)
use phpseclib4\File\ASN1\Types\PrintableString;
$x509->setDN([
    'C' => new PrintableString('US'),
    'CN' => new PrintableString('example.com'),
]);

// DN_ARRAY form (most explicit)
$x509->setDN([
    'rdnSequence' => [
        [['type' => 'id-at-countryName', 'value' => 'US']],
        [['type' => 'id-at-commonName', 'value' => 'example.com']],
    ],
]);

// Raw ASN.1 Element (for malformed-cert research and similar niche uses)
use phpseclib4\File\ASN1\Element;
$x509->setDN(new Element(base64_decode('...')));
```

Strings default to UTF8String. Use explicit `Types\PrintableString` / `Types\BMPString` / etc. when you need a specific encoding.

### `resetDN()` / `addDNProp()` / `removeDNProps()` / etc.

```php
$x509->resetDN();                              // clears all DN properties
$x509->addDNProp('O', 'phpseclib');            // appends a single property
$x509->addDNProps('O', ['org1', 'org2']);     // appends multiple under one key
$x509->removeDNProps('O');                     // removes all properties matching the name
```

All of these have explicit Subject/Issuer variants too (`addSubjectDNProp`, etc.).

### Valid DN property names

phpseclib recognizes a wide set of property name aliases (case-insensitive) — `C` / `countryName` / `id-at-countryName` all refer to the same attribute. Beyond the common ones (`C`, `ST`, `L`, `O`, `OU`, `CN`, `SN`, `GN`, `emailAddress`, `DC`, etc.), 4.0 also accepts EV-cert jurisdictional attributes (`jurisdictionC`, `jurisdictionST`, `jurisdictionL`), `businessCategory`, `organizationIdentifier`, `postalAddress`, and `x500UniqueIdentifier`, among others.

The complete list with all aliases — plus rules for postal addresses, multi-valued RDNs, custom OIDs, and the comparison-mode semantics — is in [`references/distinguished-names.md`](distinguished-names.md).

Passing an unrecognized property name throws `phpseclib4\Exception\InvalidArgumentException` unless the name is a dotted OID (matches `/^\d+(?:\.\d+)+$/`), in which case it's accepted as an arbitrary user-defined attribute type.

## Extensions

### `setExtension($name, $value, $critical = null)`

```php
public function setExtension(string $name, mixed $value, ?bool $critical = null): void
```

Any extension can be set this way. `$name` can be the symbolic name (`id-ce-keyUsage`) or the dotted OID (`2.5.29.15`). `$value` can be anything appropriate for the extension's schema. `$critical` defaults to whatever RFC 5280 says is right for that extension; pass `true` or `false` explicitly to override (phpseclib will let you set non-default values even when the RFC says you shouldn't).

```php
$x509->setExtension('id-pe-authorityInfoAccess', [
    [
        'accessMethod' => 'id-ad-ocsp',
        'accessLocation' => [
            'uniformResourceIdentifier' => 'https://ocsp.test.ca/',
        ],
    ],
    [
        'accessMethod' => 'id-ad-caIssuers',
        'accessLocation' => [
            'uniformResourceIdentifier' => 'https://crt.test.ca/test.crt',
        ],
    ],
]);
```

If an extension is already present (which RFC 5280 §4.2 forbids — "A certificate MUST NOT include more than one instance of a particular extension" — but happens occasionally in real-world non-compliant certs), `setExtension()` modifies the first occurrence only.

### `removeExtension($name)`

```php
public function removeExtension(string $name): void
```

Removes **all** occurrences of an extension. Returns nothing meaningful.

### Specialized helpers

A handful of common extensions have dedicated methods. Prefer these — they're easier to read and handle the structure correctly.

#### `addDomains($domain1, $domain2, ...)`

```php
public function addDomains(string ...$domains): void
```

Adds DNS names to `id-ce-subjectAltName`. Variadic — pass as many as you need.

```php
$x509->addDomains('example.com', 'www.example.com', '*.api.example.com');
```

If the subject DN doesn't already have `id-at-commonName` set, `addDomains()` will set it to the first domain passed.

#### `addIPAddresses($ip1, $ip2, ...)`

```php
public function addIPAddresses(string ...$ipAddresses): void
```

Adds IP addresses to `id-ce-subjectAltName`. Same shape as `addDomains()`.

```php
$x509->addIPAddresses('192.0.2.1', '2001:db8::1');
```

#### `setSubjectKeyIdentifier($value)` / `setAuthorityKeyIdentifier($value)`

```php
public function setSubjectKeyIdentifier(string|OctetString $value): void
public function setAuthorityKeyIdentifier(string|OctetString $value): void
```

Both take either a string of raw bytes or a `phpseclib4\File\ASN1\Types\OctetString`.

```php
$x509->setSubjectKeyIdentifier($keyIdBytes);
$x509->setAuthorityKeyIdentifier($issuerKeyIdBytes);
```

The Authority Key Identifier extension exists so verifiers can locate the issuer's certificate when the issuer has multiple signing keys (e.g., during key rollover). RFC 5280 § 4.2.1.1 elaborates.

#### `createSubjectKeyIdentifier($method = 1)`

```php
public function createSubjectKeyIdentifier(int $method = 1): string
```

Computes the subject key identifier from the certificate's public key per one of RFC 5280's two recommended methods. Method 1 is the default (SHA-1 of the public key's BIT STRING). Method 2 is also defined in RFC 5280 § 4.2.1.2; pass `2` to use it. Returns the computed key identifier bytes (and also installs the extension on `$x509`).

```php
$x509->createSubjectKeyIdentifier();      // method 1
$x509->createSubjectKeyIdentifier(2);     // method 2
```

#### `makeCA()`

```php
public function makeCA(): void
```

Configures the certificate as a CA cert: sets `cRLSign`, `keyCertSign`, and `digitalSignature` bits in `id-ce-keyUsage`, and sets the `cA` boolean of `id-ce-basicConstraints` to true.

```php
$x509->makeCA();
```

### `getExtension()` return shape

As noted under [Reading certificates](#reading-certificates), `getExtension()` returns:

```php
[
    'extnId' => 'id-ce-cRLDistributionPoints',    // string OID name
    'critical' => false,                           // bool
    'extnValue' => /* BaseType instance */,        // phpseclib4\File\ASN1\Types\BaseType
]
```

or `null` if the extension isn't present. To get just the value, do `$x509->getExtension($name)['extnValue']`.

## Custom extensions

For extensions phpseclib doesn't recognize natively, register the OID and the structure before calling `setExtension()`:

```php
use phpseclib4\File\ASN1;
use phpseclib4\File\X509;

$customName = 'cust';
$customOID = '2.16.840.1.101.3.4.2.99';

ASN1::loadOIDs([
    $customName => $customOID,
]);

X509::registerExtension($customName, [
    'type' => ASN1::TYPE_SEQUENCE,
    'children' => [
        'toggle' => ['type' => ASN1::TYPE_BOOLEAN],
        'num' => ['type' => ASN1::TYPE_INTEGER],
        'name' => ['type' => ASN1::TYPE_OCTET_STRING],
        'list' => [
            'type' => ASN1::TYPE_SEQUENCE,
            'min' => 0,
            'max' => -1,
            'children' => ['type' => ASN1::TYPE_OCTET_STRING],
        ],
    ],
]);

$x509->setExtension($customName, [
    'toggle' => true,
    'num' => 5,
    'name' => "\0\1\2test",
    'list' => ['hello', 'world'],
]);
```

After registering, `X509::getRegisteredExtension($customName)` returns the structure definition.

```php
public static function registerExtension(string $id, array $mapping): void
public static function getRegisteredExtension(string $id): ?array
```

`ASN1::loadOIDs()` and `X509::registerExtension()` are process-wide. Call them once at startup; subsequent `X509::load()` and `setExtension()` calls will recognize the registered extension.

## From a CSR

Passing a CSR to the `X509` constructor copies three things from the CSR:

- the public key
- the subject DN
- any requested extensions (the CSR's `extensionRequest` attribute, if present)

```php
use phpseclib4\File\CSR;

$csr = CSR::load($csrPem);
$x509 = new X509($csr);
```

This is convenient, but **be careful when acting as a CA**. A CSR can request any extensions and any subject DN, including ones you wouldn't want to grant. A common safe pattern is to construct the X509 from the CSR and then immediately strip and re-set the dangerous fields:

```php
$csr = CSR::load($csrPem);
$x509 = new X509($csr);

// Strip what the requester shouldn't be allowed to dictate
$x509->removeSubjectDNProps('id-at-commonName');
$x509->removeExtension('id-ce-subjectAltName');
$x509->removeExtension('id-ce-basicConstraints');
$x509->removeExtension('id-ce-keyUsage');
$x509->removeExtension('id-ce-extKeyUsage');
$x509->removeExtension('id-ce-cRLDistributionPoints');
$x509->removeExtension('id-pe-authorityInfoAccess');

// Set the fields the CA actually authorizes
$x509->addDomains($authorizedDomain);
// ... other policy-driven extensions ...

$pfx->sign($x509);
echo $x509;
```

What you remove vs. keep depends entirely on your CA policy. There's no safe default — even keeping `id-ce-keyUsage` from a CSR can be dangerous if the requester asks for `keyCertSign` on what's meant to be an end-entity cert.

## Signing

Two ways to sign: with a `PrivateKey` directly, or with a `PFX`.

### With a PrivateKey

```php
use phpseclib4\Crypt\EC;
use phpseclib4\File\X509;

$privKey = EC::createKey('nistp256');

$x509 = new X509($privKey->getPublicKey());
$x509->setSubjectDN('/O=demo subject');
$x509->setIssuerDN('/O=demo issuer');
$privKey->sign($x509);
echo $x509;
```

`$privKey->sign($x509)` does two things in one call: it returns the raw signature bytes, and it installs the signature into `$x509` as a side effect. So `$privKey->sign($x509); echo $x509;` gives you the full signed PEM. Don't write `echo $privKey->sign($x509);` — that prints raw signature bytes, not a PEM.

### With a PFX

```php
use phpseclib4\File\PFX;
use phpseclib4\Crypt\EC;

$caPriv = EC::createKey('nistp256');
$caCert = new X509($caPriv->getPublicKey());
$caCert->makeCA();
$caCert->setDN('O=My CA');
$caPriv->sign($caCert);

$pfx = new PFX();
$pfx->add($caPriv);
$pfx->add($caCert);

// Sign an end-entity cert with the PFX as the CA
$priv = EC::createKey('nistp256');
$x509 = new X509($priv->getPublicKey());
$x509->setSubjectDN('O=end entity');
$pfx->sign($x509);
echo $x509;
```

`$pfx->sign($x509)` does everything `$privKey->sign($x509)` does, plus:

- Auto-sets the issuer DN of `$x509` to match the subject DN of the CA cert in the PFX.
- Auto-sets `id-ce-authorityKeyIdentifier` on `$x509` from the CA cert's subject key identifier (if the CA cert has one).

This is the convenient path for "I have a CA, sign this cert with it." A bare `PrivateKey` signer doesn't do those auto-fills because keys don't know about CA certs.

### The ordering rule

**Sign last.** Configuring DNs, extensions, dates, etc. *after* signing leaves the signature stale — phpseclib doesn't auto-resign. The signing call should be the last thing you do before serializing the cert.

Re-signing an already-signed cert is fine; the `Signable` interface (see `references/asn1-constructed.md`) takes care of locating the old signature, computing a new one over the correct bytes, and installing it in the right slot.

## Output format (PEM vs DER)

```php
public function __toString(): string
public function toString(array $options = []): string
public function getEncoded(): string

public static function enableBinaryOutput(): void
public static function disableBinaryOutput(): void
```

By default, `echo $x509;` (or any `(string)$x509`) produces a PEM:

```
-----BEGIN CERTIFICATE-----
MIID...
-----END CERTIFICATE-----
```

For binary DER output:

```php
// Per-call
$der = $x509->toString(['binary' => true]);

// Or process-wide (every subsequent __toString returns DER)
X509::enableBinaryOutput();
echo $x509;                  // binary DER bytes
X509::disableBinaryOutput(); // back to PEM
```

`$x509->getEncoded()` also exists as an explicit alternative to `__toString()`; it returns whatever the current output mode dictates.

`toString()`'s `$options` array supports `'binary' => bool` to override the global mode for a single call; other option keys may be added in the future.

## Validation

Validating a certificate's signature requires knowing what root CA(s) you trust. Load them with `X509::addCA()` before calling `validateSignature()`.

### The CA store

```php
public static function addCA(string|array|Constructed|X509 $cert, int $mode = ASN1::FORMAT_AUTO_DETECT): void
public static function clearCAStore(): void
public static function getCAs(): array
```

The CA store is process-wide static state. `addCA()` appends a trust root; subsequent calls append more. `clearCAStore()` removes them all (useful for tests); `getCAs()` returns the current store as an `X509[]`.

`addCA()` accepts any of: a PEM/DER string, the same nested array structure `decodeBER()` returns, a `Constructed` object, or an already-loaded `X509` instance. The `$mode` parameter only applies when passing a string; it's one of `ASN1::FORMAT_AUTO_DETECT` (default), `ASN1::FORMAT_PEM`, or `ASN1::FORMAT_DER`.

### Basic flow

```php
X509::addCA(file_get_contents('isrg-root-x1.pem'));
// Call additional times for additional roots:
X509::addCA(file_get_contents('another-root.pem'));

$x509 = X509::load(file_get_contents('cert.pem'));

if ($x509->validateSignature()) {
    echo 'valid';
} else {
    echo 'invalid';
}
```

CA bundles can be downloaded from places like [curl's CA extract](https://curl.haxx.se/docs/caextract.html). Parsing the bundle and calling `addCA()` per cert is left to the caller.

### `validateSignature($caonly = true)`

```php
public function validateSignature(bool $caonly = true): bool
```

Checks:

- the signature itself (against the issuer's public key)
- the certificate's validity dates (against the target validation date — defaults to now)
- revocation status (if a CRL function is configured — see below)

`$caonly` controls how self-signed certs are handled:

- `$caonly = true` (default): self-signed certs return `false` unless they're in the CA store. This is what you want for normal verification flows.
- `$caonly = false`: a self-signed cert verifies if its signature is valid against its own public key. Useful for inspecting/accepting self-signed certs without first loading them as CAs.

### Validation date

```php
public static function setTargetValidationDate(\DateTimeInterface|string|null $date = null): void
public static function getTargetValidationDate(): \DateTimeInterface|string|null
```

```php
X509::setTargetValidationDate('2025-01-01');
$date = X509::getTargetValidationDate();
```

If unset, defaults to the current time. Pass `null` to reset to "now."

### Recursion limit for intermediate fetching

```php
public static function setRecurLimit(int $count): void
```

```php
X509::setRecurLimit(5);    // default
X509::setRecurLimit(-1);   // unlimited (use with caution)
X509::setRecurLimit(0);    // don't fetch intermediates at all
```

When validating a chain, phpseclib may need to download intermediate certificates referenced via the `id-pe-authorityInfoAccess` extension's `caIssuers` field. The recursion limit prevents infinite loops in malicious or misconfigured chains.

### URL fetching toggle

```php
public static function disableURLFetch(): void
public static function enableURLFetch(): void
```

```php
X509::disableURLFetch();   // do not auto-download intermediates
X509::enableURLFetch();    // re-enable (the default)
```

### keyUsage and basicConstraints checks

```php
public static function checkKeyUsage(): void
public static function ignoreKeyUsage(): void
public static function isCheckKeyUsageEnabled(): bool

public static function checkBasicConstraints(): void
public static function ignoreBasicConstraints(): void
public static function isCheckBasicConstraintsEnabled(): bool
```

```php
X509::ignoreKeyUsage();          // skip the issuer keyUsage check
X509::checkKeyUsage();           // re-enable
X509::isCheckKeyUsageEnabled();  // query the current state

X509::ignoreBasicConstraints();  // skip the basicConstraints check
X509::checkBasicConstraints();   // re-enable
X509::isCheckBasicConstraintsEnabled();
```

By default, `validateSignature()` checks that the issuer's keyUsage includes `keyCertSign` and that basicConstraints' `cA` is true. Some legacy chains fail these checks despite being functionally trustworthy; the toggles let you skip them when you know what you're doing.

### DN comparison mode

```php
public static function strictDNComparison(): void
public static function looseDNComparison(): void
public static function isStrictDNComparisonEnabled(): bool
```

Strict comparison (the default) treats two DNs as different if any RDN value uses a different ASN.1 string type — `UTF8String "ACME"` ≠ `PrintableString "ACME"`. Loose comparison compares the underlying string values only.

```php
X509::looseDNComparison();           // be permissive about string types
X509::strictDNComparison();          // require exact ASN.1 type match (default)
X509::isStrictDNComparisonEnabled(); // query the current state
```

Affects how phpseclib decides whether an issuer DN matches a CA cert's subject DN during chain validation. The strict default is correct per RFC 5280, but some real-world certificate chains were issued with mixed string types and only validate with loose comparison.

### CRL revocation

```php
public static function setCRLLookupCallback(\Closure $func): void
```

To enable revocation checking during `validateSignature()`, supply a callback that takes a CRL distribution point URL and a serial number, and returns whether the serial is revoked:

```php
use phpseclib4\Math\BigInteger;

X509::setCRLLookupCallback(function (string $url, BigInteger $serial): bool {
    // Return true if the serial is revoked, false otherwise.
    // Look up your CRL however you like — fetch from $url, query a local cache, etc.
    $crl = CRL::load(/* ... */);
    return $crl->isRevoked($serial);
});
```

The callback receives the CDP URL from the certificate being validated and the certificate's serial number; the implementation is up to you. phpseclib doesn't fetch CRLs itself — it asks your callback whether a specific serial is revoked, and your code decides where to look. See `references/crl.md` for the CRL-side details (parsing, `isRevoked()`, etc.).

**Scope note: this is CRL-only.** phpseclib 4.0.0 does not support OCSP for revocation checking. That's less of a gap than it once was — the CA/Browser Forum made OCSP optional in 2023, and Let's Encrypt (the largest CA) shut down its OCSP responders in August 2025, citing privacy concerns and moving exclusively to CRLs. A future 4.0.x minor release may add OCSP — adding methods isn't a BC break. If you need OCSP now, you'd have to do it outside phpseclib and short-circuit the callback accordingly.

### URL validation

```php
public function validateURL(string $url): bool
```

```php
if ($x509->validateURL('https://www.example.com/path')) {
    echo 'cert is valid for this URL';
}
```

Checks that the certificate is valid for the given URL — matches the host against `id-ce-subjectAltName` (or `id-at-commonName` as fallback), checks the dates, etc. This is a wrapper around `validateSignature()` plus hostname matching; it does not perform a TLS handshake.

### Chain inspection

```php
public function getValidationChain(): array
```

```php
$chain = $x509->getValidationChain();
// $chain is an X509[] where:
//   $chain[0]                       => $x509 (the cert being validated)
//   $chain[count($chain) - 1]       => the CA root
```

Useful for displaying or auditing the full chain that `validateSignature()` walked through.

### `isIssuerOf($subject, $expectedKeyUsage = [])`

```php
public function isIssuerOf(self|CRL|Choice|array $subject, array $expectedKeyUsage = []): bool
```

Tests whether this `X509` (as a CA cert) issued the given subject — another `X509`, a `CRL`, a `Choice`, or an array containing either an `issuerAndSerialNumber` or a `subjectKeyIdentifier`. The optional `$expectedKeyUsage` argument is an array of key-usage bit names that the issuer cert must have set (e.g., `['keyCertSign']`).

Used internally during chain validation; usually you'd just call `validateSignature()` and let phpseclib walk the chain. `isIssuerOf()` is useful when you want to ask "did this specific CA cert sign that specific thing" without doing a full validation.

## ArrayAccess

Every `X509` object implements `ArrayAccess`, `Countable`, and `Iterator`. Because of the `$rules` that `X509::load()` registers with `ASN1::map()` (see [What an X509 object is](#what-an-x509-object-is)), the ArrayAccess path returns the *same typed objects* the helper methods do — it's not a lower-level alternative.

```php
// These return the exact same PublicKey object:
$key = $x509->getPublicKey();
$key = $x509['tbsCertificate']['subjectPublicKeyInfo'];

// Other fields are similarly pre-decoded:
$serial    = $x509['tbsCertificate']['serialNumber'];          // BigInteger
$validity  = $x509['tbsCertificate']['validity'];              // array with notBefore/notAfter
$notBefore = $x509['tbsCertificate']['validity']['notBefore']; // DateTimeInterface
$subject   = $x509['tbsCertificate']['subject'];               // pre-mapped DN structure
```

When to use the helpers: when they exist for what you want. They're shorter to write and throw clear typed exceptions on bad inputs.

When to use ArrayAccess: when there isn't a helper for the specific field, when you need to walk multiple instances of an extension (since `getExtension()` only returns the first), when you're writing tooling that operates on certificate fields phpseclib doesn't model with a helper, or when the helper would throw and you want to inspect the unparsed bytes via the underlying `Constructed`:

```php
// Inspect the raw encoded bytes of any field by reaching for the Constructed and
// calling getEncoded():
$rawSubjectBytes = $x509['tbsCertificate']['subject']->getEncoded();
```

This works because every value in the ASN.1 tree is either a typed object (`PublicKey`, `BigInteger`, `DateTimeInterface`, a `BaseType` subclass, etc.) or a `Constructed`, and `Constructed` has a `getEncoded()` method that returns the original encoded bytes.

The fields available via ArrayAccess map directly to the names in the [RFC 5280 ASN.1 schema](https://www.rfc-editor.org/rfc/rfc5280#appendix-A) — `tbsCertificate`, `signatureAlgorithm`, `signature`, and within `tbsCertificate`: `version`, `serialNumber`, `signature`, `issuer`, `validity`, `subject`, `subjectPublicKeyInfo`, `issuerUniqueID`, `subjectUniqueID`, `extensions`. See `references/asn1-constructed.md` for the deep mechanics of how the `Constructed` objects work and how `$rules` are applied during decode.
